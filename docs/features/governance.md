# Lobe Ownership & Governance

Cerebrofy can derive **who owns each lobe** from git history and the call graph, then use that ownership to generate CODEOWNERS, suggest reviewers, and evaluate reporting-only governance rules.

Unlike a hand-maintained `CODEOWNERS` file, ownership here follows the code that is actually being touched. New modules get a fallback owner instead of no reviewer, and lobes that are heavily called from elsewhere get a co-reviewer from the caller lobe.

## Ownership Strategies

Configure the strategy in `.cerebrofy/config.yaml`:

```yaml
governance:
  strategy: git-blame        # git-blame (default) \| explicit \| hybrid
  auto_sync_codeowners: false
  fallback_owner: "@tech-leads"
  activity_days: 90
```

| Strategy | How ownership is assigned |
|----------|--------------------------|
| `git-blame` | Author with the most blamed lines across the lobe's neurons. |
| `explicit` | Owners declared in `.cerebrofy/team.yaml`. |
| `hybrid` | Blame line counts weighted by commits in the last `activity_days` (max 1.5× boost). |

### Explicit Ownership File

```yaml
# .cerebrofy/team.yaml
default_owner: "@tech-leads"
lobes:
  auth:
    owners: ["alice@co.com", "@alice"]
  graph:
    owners: ["bob@co.com"]
```

If a lobe is absent from `lobes`, `default_owner` is used. If neither is present, CODEOWNERS falls back to `governance.fallback_owner`.

### Bus Factor

Bus factor is the number of authors needed to cover more than half of a lobe's blamed lines. A bus factor of 1 is treated as critical in CODEOWNERS comments.

## Generate CODEOWNERS

```bash
cerebrofy governance generate-codeowners              # write ./CODEOWNERS
cerebrofy governance generate-codeowners --dry-run    # print only
cerebrofy governance generate-codeowners --output .github/CODEOWNERS
cerebrofy governance generate-codeowners --force      # overwrite a manual file
cerebrofy governance sync                             # regenerate ./CODEOWNERS in place
```

`sync` is the explicit equivalent of the opt-in build hook below: it regenerates `<repo>/CODEOWNERS` and, like the build hook, refuses to overwrite a hand-maintained file. Use `generate-codeowners --force` when you intentionally want to replace one.

Generated files start with:

```text
# Auto-generated by cerebrofy governance — 2026-06-19
# DO NOT EDIT MANUALLY — run `cerebrofy governance generate-codeowners` to update.
```

The generator refuses to overwrite a file that does not carry this header unless `--force` is passed. Each block includes the lobe's bus factor; cross-lobe callers contribute a co-reviewer; lobes with no commit history receive the configured fallback owner. If the repository itself has no commits at all, generation fails with `[NO_GIT_HISTORY]` instead of emitting an all-fallback file.

`tests/` is treated as shared ownership: every contributing author from the test lobe (or, when there is no test lobe, every primary owner) is listed.

### Sync During Build

Set `governance.auto_sync_codeowners: true` to regenerate CODEOWNERS after the health snapshot in `cerebrofy build`. The sync is non-fatal and still refuses to clobber a hand-maintained file.

## Suggest Reviewers

```bash
cerebrofy governance suggest-reviewers --pr 142
cerebrofy governance suggest-reviewers --diff origin/main --format json
```

Roles:

| Role | Source |
|------|--------|
| `primary` | Owner of a changed lobe. |
| `secondary` | Owner of a lobe connected to a changed lobe by cross-lobe call edges. |
| `backup` | Recent contributor to the changed lobe, excluding primary/secondary. |

PR mode uses the GitHub CLI (`gh`). If `gh` is missing or unauthenticated the command reports `[GH_NOT_AUTHENTICATED]` and suggests `gh auth login`. Diff mode uses local read-only git.

If a multi-agent coordination registry is present at `cerebrofy.coordination.registry.active_agent_emails()`, agents currently active in a lobe are excluded from suggestions. When that module is absent the exclusion is skipped gracefully.

## Governance Rules

Add a `governance` block to the existing `.cerebrofy/arch-rules.yaml` — there is no second config file:

```yaml
governance:
  rules:
    - name: high-blast-requires-two-reviews
      description: Any PR touching blast_radius > 30 requires 2 approvals
      check:
        if_blast_radius: { gt: 30 }
        then_require_approvals: 2

    - name: silo-lobes-require-backup
      description: Lobes with bus_factor=1 require a non-owner reviewer
      check:
        if_bus_factor: { eq: 1 }
        then_require_non_owner_review: true

    - name: new-neurons-require-coverage
      description: Any PR adding new neurons must include tests
      check:
        if_new_neurons: true
        then_require_test_file: true
```

```bash
cerebrofy governance check-rules --lobe auth
cerebrofy governance check-rules --diff origin/main --format json
cerebrofy governance check-rules --pr 142
```

Evaluation returns `PASS`, `WARN`, or `FAIL` per rule with a reason.

- `PASS` — the condition does not apply, or the requirement is satisfied.
- `FAIL` — the condition applies and the requirement is demonstrably violated (e.g. no test file changed, not enough approvals recorded).
- `WARN` — the condition applies but the requirement cannot be verified without PR metadata (diff mode has no approvals/reviews).

`check-rules` is **reporting only**. It does not enforce anything, does not modify the repository, and exits 0 even when a rule fails.

## Error Codes

| Code | Meaning |
|------|---------|
| `NO_INDEX` | `cerebrofy.db` not found — run `cerebrofy build` first. |
| `NO_GIT_HISTORY` | Repository has no commit history to compute blame from. |
| `GH_NOT_AUTHENTICATED` | A `--pr` request needs `gh auth login`. |
| `NO_GOVERNANCE_RULES` | No `governance.rules` block exists in arch-rules.yaml. |

## MCP Tool

```
cerebrofy_governance(action="generate-codeowners", format="json")
cerebrofy_governance(action="suggest-reviewers", pr=142)
cerebrofy_governance(action="check-rules", lobe="auth", format="json")
```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `action` | string | ✅ | `generate-codeowners` · `suggest-reviewers` · `check-rules` |
| `pr` | integer | — | GitHub PR number — used by `suggest-reviewers` and `check-rules` (requires an authenticated `gh`) |
| `lobe` | string | — | Restrict output to a specific lobe |
| `format` | string | — | `markdown` (default) or `json` |

**Output:** for `generate-codeowners`, the CODEOWNERS file content; for `suggest-reviewers`, a reviewer table; for `check-rules`, a PASS/WARN/FAIL summary with per-rule reasons.

Error codes: `[NO_INDEX]` when no index exists; `[NO_GIT_HISTORY]` when ownership is requested from a repository with no commits; `[CONFIG_ERROR]` when `.cerebrofy/config.yaml` or `.cerebrofy/team.yaml` is malformed; `[GH_NOT_AUTHENTICATED]` when `gh` is unavailable; `[NO_GOVERNANCE_RULES]` when no `governance.rules` block is configured.

The tool is read-only — it never writes CODEOWNERS; call the CLI for that.

## Integration Points

- **Configuration** — `governance` block in `.cerebrofy/config.yaml` controls strategy and auto-sync
- **Architecture rules** — `governance.rules` lives in `.cerebrofy/arch-rules.yaml`
- **Coordination** — active agents are excluded from reviewer suggestions
