# Releasing

Cerebrofy uses [python-semantic-release](https://python-semantic-release.readthedocs.io/) for automated releases.

## Release Process

Releases are triggered automatically by conventional commit messages on the `master` branch. The release version is determined by the commit message type:

| Commit Type | Version Bump | Example |
|-------------|-------------|---------|
| `fix:` | Patch (1.0.x) | `fix: resolve crash on empty index` |
| `feat:` | Minor (1.x.0) | `feat: add cerebrofy synthesize command` |
| `feat!:`, `fix!:` | Major (x.0.0) | `feat!: change default embedding model` |
| `chore:`, `docs:`, `refactor:`, `test:`, `style:`, `ci:` | No release | — |

## Making a Release

1. Ensure all changes are merged to `master`
2. Use conventional commit messages (see below)
3. python-semantic-release will automatically:
   - Determine the next version number
   - Generate a changelog from commit messages
   - Create a GitHub release
   - Publish to PyPI

## Conventional Commit Format

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

### Types

| Type | Description |
|------|-------------|
| `build` | Changes that affect the build system or external dependencies |
| `ci` | Changes to CI configuration files and scripts |
| `docs` | Documentation only changes |
| `feat` | A new feature |
| `fix` | A bug fix |
| `perf` | A code change that improves performance |
| `refactor` | A code change that neither fixes a bug nor adds a feature |
| `style` | Changes that do not affect the meaning of the code (white-space, formatting, etc.) |
| `test` | Adding missing tests or correcting existing tests |
| `chore` | Other changes that don't modify src or test files |

### Breaking Changes

Add `!` after the type/scope to indicate a breaking change:

```
feat!: remove deprecated cerebrofy migrate command
```

Or add a `BREAKING CHANGE:` footer:

```
feat: change default embedding model

BREAKING CHANGE: embedding_model default is now `none` instead of `local`
```

## Example Commit Messages

```bash
# Patch release
git commit -m "fix: handle missing state_hash in cerebrofy_map.md"

# Minor release
git commit -m "feat: add cerebrofy synthesize command (Idea #24)"

# Minor release with scope
git commit -m "feat(cli): add --format json option to cerebrofy review"

# Major release
git commit -m "feat!: change cerebrofy build to require explicit --confirm flag"
```

## Changelog

The changelog is auto-generated by python-semantic-release from commit messages. See `CHANGELOG.md` for the release history.

> **Note:** `CHANGELOG.md` is auto-generated — do not edit manually.
